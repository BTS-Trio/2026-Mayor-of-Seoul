# 질문에 따른 공약 기사 초안 생성

## 현재 구현

질문 → BM25 근거 검색 → 후보별 관련 원문 발췌 → 문장별 PDF 인용 연결 → DB 저장 → 검토·승인·반려 순서로 동작합니다. 저장된 6문장 예시 기사를 복사하는 방식이 아닙니다. 실제 외부 AI 호출·LLM 문장 재작성은 하지 않으며 API 키가 필요 없습니다. 제목과 연결 문장은 정해진 형식이고, 질문에 따라 발췌 근거가 달라집니다.

현재 준비된 데이터는 주거 공약입니다. 교통·교육 등 다른 분야 또는 모든 분야의 공약을 요구하면 범위 부족을 안내하고 저장하지 않습니다. 근거가 없는 질문도 내용을 만들어 채우지 않습니다. 검색은 키워드 기반이므로 모든 자연어 질문을 이해하는 것은 아닙니다.

## 사용 순서

1. 두 서버 중 방송사 서버 실행 후 개표 데스크의 ‘공약 검색 · 질문으로 새 기사 초안 만들기’를 엽니다. 이 기능에는 개표 송신 서버가 필수는 아닙니다.
2. 질문 입력, 필요하면 후보 선택·사퇴 포함 여부를 지정합니다.
3. ‘질문으로 기사 초안 만들기’를 누릅니다.
4. 생성된 문장과 PDF 원문을 대조합니다.
5. ‘이 초안 검토·승인하기’에서 검토자·처리 사유를 입력합니다.
6. 새로고침한 뒤에도 검색 화면의 저장 목록과 검토 화면의 처리 이력에서 다시 확인할 수 있습니다.

질문 예시:

- 강도윤의 청년 지원 예산은 얼마인가? → 12,000가구·48개월·총 864억 원을 설명하는 원문 발췌.
- 강도윤 주거 공약의 재원 조달 방법은? → 시비 70%·기금 30% 원문 발췌.
- 오세훈의 월세 지원 공약은? → 기존 수집 PDF의 관련 문구와 실제 인용 쪽수.
- 후보별 주거 공약을 비교해줘 → 기본 출마 후보 5명의 관련 근거. 사퇴 포함 선택 시 6명.

모든 가상 공약과 개표 수치는 교육용 설정이며 오세훈의 공약 일부만 실제 수집 원문입니다. 공약을 이행 사실로 쓰지 않습니다. 현재 발췌 초안은 정책의 우열·실현 가능성·이행 여부를 판단하지 않습니다.

## 저장과 테이블

기본 DB는 `demo/housing-review-demo-v2.sqlite3`입니다. HOUSING_REVIEW_DB로 명시한 경우 해당 경로에 저장합니다.

- ARTICLE: 새 ID·제목·본문·상태.
- ARTICLE_EVIDENCE: 각 문장과 검색 청크·사퇴 근거 연결.
- drafts.payload: 질문·후보 필터·생성 방식·발췌 문구·검색 범위·원문 지문.
- FACT_CHECK / REVIEW / audit: 검사 및 승인·반려 처리 이력.

실행 중 생긴 기사는 DB에 저장합니다. 저장소의 초기 CSV·housing_article.json 파일을 덮어쓰지 않습니다. 득표 예시 기사의 저장 기능을 추가한 것은 아닙니다.

## API

| 메서드·주소 | 요청·응답 |
| --- | --- |
| POST /api/housing/generate | question, candidate(선택), include_withdrawn(기본 false) → 새 id, 문장, 근거, 검사 결과, review_url |
| GET /api/housing-review/drafts | 최근 저장 초안 30개와 상태 |
| GET /api/housing-review/drafts/{id} | 저장 초안·질문·문장·현재 검사 결과 |
| POST /api/housing-review/drafts/{id}/decision | 기존 승인·반려 경로 재사용 |

생성 성공은 201입니다. 근거 없음·다른 분야·사퇴 포함 누락·상충된 후보 조건은 422와 구체적인 사유를 반환합니다. 질문 길이는 2~500자입니다. 저장 조회 ID가 없으면 404, 검사 실패 또는 이미 처리한 기사에 재승인을 시도하면 409입니다.

생성된 초안의 generation_mode는 retrieval_extract, 검사 ai_mode는 not_used입니다. 기존 예시 검수의 AI fixture와 구분합니다. 원문에 없는 발췌, 수치·후보·쪽수·본문 변경, 생성 후 원문 변경, 비교 대상 후보의 근거 누락은 승인 차단 대상입니다. 이 검사는 원문과 출력의 일치를 확인하며, 기사 충분성·문맥·질문에 대한 적절성은 사람이 검토해야 합니다.

## 확인 범위

질문별 발췌 변화, 실제/가상 PDF 인용, 사퇴 제외·포함, 근거 부족, 변경된 문장 차단, DB 저장·재조회·정규 테이블 연결, 생성 기사 승인·반려를 자동 검사합니다. Chrome에서는 검색 화면에서 생성 → 새로고침 후 저장 목록 확인 → 해당 기사 검토 → 승인 → 새로고침 후 상태 보존을 검사합니다.
