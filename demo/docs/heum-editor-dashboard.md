# 흠 · 개표 데스크 화면 설계와 시연

## 오늘 시연할 흐름

1. 8001·8000 서버를 실행한 뒤 `http://127.0.0.1:8000/offline-preview.html`을 열고 **처음부터 재생**을 누른다.
2. 표가 집계되면 **예시 기사 만들기**를 누른다. 기사에 가상 집계 시각, 후보 득표수, 근거 행 ID와 공식 출처가 표시된다.
3. 정상 사례에서는 검증 통과를 확인하고 **승인**한다. 화면에 해당 기사에 연결된 개표 ID와 승인 결과가 표시된다.
4. 오류 사례에서는 **득표수 오류 넣기**를 체크하고 예시를 다시 만든다. 집계와 초안의 표 차이를 표시하고 승인 버튼을 잠근다. 반려 사유를 적고 **반려**한다.
5. 다음 개표 데이터가 도착해도 예시 기사는 작성 당시의 개표 ID를 유지한다. 새 수치로 기사를 만들려면 버튼을 다시 누른다.

화면의 시험용 기사는 현재 개표의 선두 후보를 바탕으로 브라우저가 작성한다. AI 기사 및 태의 검증·승인 서버를 연결하면 서버가 돌려주는 결과와 사유를 표시한다. 시연 화면의 승인·반려는 현재 탭에서만 표시되며 실제 기사 게시나 서버 저장을 수행하지 않는다.

## 윤·태 연결에 필요한 정보

| 담당 | 화면에 필요한 값 또는 동작 |
| --- | --- |
| 윤 | 기사 ID, 제목, 본문, 집계 ID, 근거 행 ID와 근거 출처 링크 |
| 태 | 검증 통과 여부와 실패 사유, 승인·반려 상태, 반려 사유 저장 요청과 응답. 서버에서도 검증 실패 기사의 승인 요청을 거절한다. |
| 흠 | 개표 WebSocket과 편집 화면의 상태 표시, 검증·승인 요청 연결, 화면 검수와 발표 장면 녹화 |

실제 URL과 응답 필드는 윤·태의 API 명세가 나오면 확정한다. 승인 판단은 기사 초안이 가리키는 개표 시점의 근거와 대조한다.

## 발표 첫 장면 구성

- 교육용 개표 재생임을 밝혀 가상 집계 순서와 공식 원본을 구분한다.
- 개표가 움직이는 장면에서 예시 기사와 근거 ID를 함께 보여 준다.
- 100표 오류를 넣어 승인 버튼이 잠기는 장면을 보여 준다. 반려 사유를 기록하고 정상 예시를 승인한다.
- 발표에서는 시연용 처리와 팀 서버 기능의 연결 여부를 명시한다.
