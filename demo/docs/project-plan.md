# 프로젝트 1 작업 계획

## 기획

- 과제명은 **RAG 모델 기반의 선거 보도 구성하기**다. 서울시장 선거를 1차 범위로 제안한다.
- 보도 질문은 **모의 개표가 진행되는 동안 서울시장 후보 간 득표 격차는 어떻게 움직이며, 최종 확정 수치와 어떻게 연결되는가?**이다. 실제 선거 보도와 가상 재생 질문을 명시적으로 구분한다.
- 승인 확인 항목은 3인 팀(원문 4~6명), 발표·평가 11월 27일(원문 기준), 수업 지정 Python 버전과 팀 환경 차이다.
- 시연에서 특정 후보 지지·공격, 추측성 당선 예측, 출처 없는 수치가 나오지 않게 점검한다. 후보색에만 순위나 상태 의미를 부여하지 않는다. 원문 링크와 필요한 분량의 인용을 사용한다. 합성 영상·음성 사용 시 화면과 발표 자료에 표시한다.

## 구현 순서 및 완료 기준

1. 최신 데이터의 표시 기준시각과 실제 수신시각, 웹 연결·오류 상태를 구분한다. 현재 개표 재생의 데이터와 UI 골격을 준비했다.
2. 공식 후보·공약·발표·정정 문서에서 주제 관련 근거를 수집한다. 질문을 받으면 검색한 내용과 문서 제목·기관·URL·게시일·수집일·근거 ID를 보인다.
3. 기사 초안의 모든 사실 문장에 근거 ID를 연결한다. 가상 집계 수치를 쓰는 문장에는 가상임을 표시한다.
4. 지역·후보·기준시각·득표수·득표율·계산 오류·누락 출처를 검증한다. 규칙 실패 또는 AI 보조 판정 불일치는 승인 차단과 실패 사유 기록으로 처리한다.
5. 사람 승인에는 승인자·시간·사유 및 수정 전후를 기록한다. 초안을 만든 사람이 아닌 팀원이 검토한다. 검증을 통과한 시연용 기사만 편집장이 승인한다.
6. 정상 흐름 1건, 오류·불일치 흐름 1건 이상(예: 서울 스냅샷을 부산으로 기술)을 리허설한다. 대본·CG·자막은 승인 기사에 연결한다. 약 20분 이내 FHD MP4와 핵심 시연 장면을 준비한다.

선택 고도화 항목인 Kafka, 검색엔진, CMS, 외부 팩트체크, AI Agent, 파인튜닝은 필수 경로 통합 후 판단한다. 원문 평가 배점은 프로젝트 이해 25, 창의성과 혁신 20, 협업 20, 수행 태도와 목표관리 20, 발표 15다. 평가표는 5단계 루브릭으로 작성한다.
